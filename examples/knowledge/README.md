# examples/knowledge/ —— 知识库示例（全部虚构）

这里的三份文件是**虚构示例**，用来演示 EarShot 期望的材料写法，不是真实经历。
请把它们当作「格式参照」，替换成你自己的简历和项目。

| 文件 | 演示什么 |
|---|---|
| `示例_自我介绍与HR准备.md` | 自我介绍 / 离职原因 / 加班 / 期望薪资 这类 HR 题的「可照念」写法：先给结论，再给一句支撑，别写成作文 |
| `示例_项目A_推荐系统.md` | 一个项目一份材料的标准结构：一句话 → 为什么这样设计 → 效果怎么量出来 → 踩过的坑 → 我负责什么 |
| `示例_项目B_质检Agent.md` | 另一个项目：重点演示「边界与取舍」（不让模型生成关键字段）和「怎么验收」的写法 |

## 怎么用

```powershell
# 拷进 _base/ 试跑，看看提词器会怎么检索、怎么改写答案
Copy-Item examples/knowledge/*.md knowledge/_base/
```

试完记得删掉这几份虚构示例（`Remove-Item knowledge/_base/示例_*.md`）——
真正的面试材料要换成你自己的。

## 写自己的材料

1. 先看 [knowledge/README.md](../../knowledge/README.md) 的「目标覆盖度」清单，知道该准备哪些文件；
2. 用 [docs/喂给AI的面试资料整理提示词.md](../../docs/喂给AI的面试资料整理提示词.md)
   把简历 / 项目笔记 / JD 交给 AI，让它按同一结构生成初稿；
3. **逐条核实数字和事实**（AI 只许整理，不许编造），再放进 `knowledge/`；
4. 跑 `python tools/kb_audit.py` 体检。

## 记住三件事

- **空知识库 = 没有答案**：提词器只从你放进去的材料里检索，不会从大模型的世界知识里编。
- **材料越像你本人，答案越像你自己说的话**：写你真正做过的事、真正的数字、真正的取舍。
- **别混别人的同题材面经**：实测同题材材料会抢排名，hit@1 会从 89.7% 掉到 41.0%。
