# knowledge/ —— 你的面试材料放这里

EarShot 的「快答线」不从大模型的世界知识里编答案，而是**先从你放进这里的材料里检索**，
再让模型把检索到的片段改写成「可以照念」的口语回答。所以这个目录里放什么，直接决定
面试时屏幕上会出现什么。

## 放什么

- 简历（.md / .txt）
- 项目报告 / 复盘（一个项目一个文件，文件名本身就是检索特征，取清楚些）
- 自我介绍稿、HR 常见问题准备稿
- 面试复盘、面经整理
- 任何「你希望被问到时能照着自己的话答」的材料

支持的格式：`.md`、`.txt`（默认 glob 见 `config/settings.example.json` 的 `corpus_globs`，可以自己改成别的目录或格式）。

## 怎么组织

内容会被切成 300~700 字的块（`server/knowledge.py`），文件名会加权参与打分，所以：

| 建议 | 原因 |
|---|---|
| 一个项目一个文件，文件名写全（如 `项目A_推荐系统.md`） | 文件名参与检索打分，口语提问里常出现项目名 |
| 数字、指标写进句子里，不要只放表格 | 检索按句子匹配，散落的数字很难被召回 |
| 小标题写成人话（「为什么用行为树」） | 面试官的口语提问更容易和标题对上 |
| 别放 10 万字的原始文档 | 检索会变慢、命中会变糊，精炼比量大重要 |

## 示例

`examples/knowledge/` 里有三份**虚构**的示例材料，可以直接拷进来试跑：

```powershell
Copy-Item examples/knowledge/* knowledge/
```

> ⚠️ `knowledge/` 下的内容默认被 `.gitignore` 忽略（只保留本文件和 `examples/`），
> 你自己的简历与项目材料不会被提交到 GitHub。
