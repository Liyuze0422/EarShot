# knowledge/ —— 先填这里，再开始面试

> ⚠️ **先填充你自己的专属语料，再开始面试。**
> 提词器不会从大模型的世界知识里编答案 —— 它**只**从你放进这里的材料里检索，
> 再把检索到的片段改写成「可以照念」的口语回答。
> 材料空 / 材料泛 → 屏幕上就没有答案；材料越贴近你本人 → 答案越像你自己说的话。

---

## 一分钟上手

1. **准备材料**：简历、每个项目的笔记（做了什么 / 为什么这么做 / 数字 / 踩过的坑）、
   目标公司的 JD、面经。没有现成笔记？用
   [docs/喂给AI的面试资料整理提示词.md](../docs/喂给AI的面试资料整理提示词.md)
   里的提示词让 AI 先帮你整理成初稿（数字必须自己核实）。
2. **放进本目录**：通用材料放 `_base/`，某家公司专用的放 `<公司名>/`。
   文件名写清楚（文件名就是检索键，详见下文「怎么组织」）。
3. **切资料包**：面试哪家就切哪个包（`tools/profiles.py --use <名>`），
   或直接改 `config/settings.json` 的 `corpus_profile`。
4. **体检**：`python tools/kb_audit.py` —— 它会告诉你哪些材料切得太碎、
   哪些文件名打不中、哪些块太短会被丢。

支持的格式：`.md`、`.txt`（默认 glob 见 `config/settings.example.json` 的
`corpus_globs`，可以自己改成别的目录或格式）。

## 填成什么样才算合格（示例）

一份合格的项目材料长这样 —— **每个 `##` 小节写成人话，且自带主语**（检索是按块取的，
块被单独拎出来时不能看不出在说哪个项目）：

```markdown
# 项目A · 某电商推荐系统（虚构示例，替换成你自己的项目）

## 一句话
给一家垂直电商做的商品推荐服务，日活 8 万，推荐位带来的成交占全站 12%。

## 为什么用双塔召回 + 粗排重排
一开始只有协同过滤，冷启动商品完全推不出去。改成「双塔召回 + 粗排 + 精排」三段式：
双塔负责从 20 万商品里召回 500 个候选（离线训练，线上只做向量检索，P99 12ms）；
粗排用轻量 GBDT 砍到 60 个；精排才是原来的深度模型。

## 效果是怎么量出来的
上线做了 14 天 A/B：推荐位点击率 +18.4%，人均成交额 +6.9%，退货率没有变化；
冷启动商品的曝光占比从 3.1% 提到 11.7%。

## 踩过的坑
1. 特征穿越：早期把「下单时间」写进了训练特征，离线 AUC 0.83，线上直接掉 6 个点。
   后来统一用特征快照表，训练样本严格按曝光时刻取特征。
2. 向量检索的索引没做增量，每天凌晨重建要 40 分钟；换成 HNSW 增量写入后降到 2 分钟。

## 我在里面做了什么
- 负责召回与粗排两段：特征口径、离线评估脚本、上线灰度
- 设计了冷启动兜底：新商品没有行为数据时，用内容向量走另一条召回通路
```

另外三份完整示例（自我介绍与 HR、项目 A、项目 B）在
[`examples/knowledge/`](../examples/knowledge/) 里，可以直接拷进来试跑：

```powershell
Copy-Item examples/knowledge/*.md knowledge/_base/
```

## 目标覆盖度：填到什么程度算「够」

这不是硬性要求，但**按这张表填满的人，面试体验明显不一样**（缺一块，那一类问题就会答得空）。
更省事的办法：把这张表连同下面的提示词页一起交给 AI，让它按表逐份生成初稿，你再核实数字。

### A. 通用底座（`knowledge/_base/`）

| 文件（示例命名） | 用途 | 建议篇幅 |

| 文件 | 作用 |

## 怎么组织（这几条直接决定检索命中率）

内容会被切成 300~700 字的块（`server/knowledge.py`），**文件名在检索词袋里权重 4 倍**，
所以文件名不是标签，是检索键：

| 建议 | 原因 |
|---|---|
| 一个项目一个文件，文件名写全（如 `项目A_推荐系统.md`） | 文件名参与检索打分，口语提问里常出现项目名 |
| 数字、指标写进句子里，不要只放表格 | 检索按句子匹配，散落的数字很难被召回 |
| 小标题写成人话（「为什么用行为树」） | 面试官的口语提问更容易和标题对上 |
| 每个 `##` 小节 60~700 字，且自带主语 | 块被单独取出时不能看不出在说哪个项目 |
| 别放 10 万字的原始文档 | 检索会变慢、命中会变糊，精炼比量大重要 |
| 别把别人的面经 / 培训机构的「XX 面试宝典」混进 `_base/` | 同题材材料会抢排名：实测 hit@1 会从 89.7% 掉到 41.0% |

更细的规则（topic_terms 对齐、块切分边界、实测数据）见
[docs/知识库整理清单.md](../docs/知识库整理清单.md)。

## 让 AI 帮你把材料整理成这个结构

一份可直接复制给 DeepSeek / ChatGPT / Claude / Kimi 的提示词，会按上面的「目标覆盖度」
逐份生成初稿：**[docs/喂给AI的面试资料整理提示词.md](../docs/喂给AI的面试资料整理提示词.md)**
（Wiki 页面：`喂给AI的面试资料整理提示词`）。

流程只有三步：

1. 准备好原始材料（简历、项目笔记、JD、面经）；
2. 把提示词 + 材料黏给 AI，让它按「目标覆盖度」逐份输出 Markdown；
3. **逐条核实数字和事实**（AI 只许整理、不许编造），删掉不成立的，再把文件放进本目录，
   跑 `python tools/kb_audit.py` 体检。

## 体检

```powershell
python tools/kb_audit.py            # 只体检 _base/
python tools/kb_audit.py --all      # 连公司包一起看
```

它会报：块太短会被丢、文件名不含主题词、话题词没对齐、材料分布不均等结构问题。
**面试前跑一遍，比多背十道题有用。**

## 隐私

> ⚠️ `knowledge/` 下的内容默认被 `.gitignore` 忽略（只保留本文件和 `examples/`），
> 你自己的简历与项目材料不会被提交到 GitHub。

- 只把材料留在本机；不要把 `knowledge/` 整个目录发给别人。
- 用 AI 整理材料时，注意不要上传身份证、银行卡、前公司机密等文件。
- 本目录里除本文件外，其他文件都只属于你自己。
