# 从自用副本迁移到正式版

如果你手里有一个更早的、自己改过的版本（下面叫**旧副本**），这份文档帮你把它换成正式版，
同时**一行代码都不用改**——你的材料、词表、模型路径、密钥全部原样带过来。

## 为什么要换

旧副本把**你的私有配置写死在代码里**：材料路径在 `knowledge.py`，模型路径在 `main.py`，
密钥路径在 `answer.py`。结果就是两个真相：

- 旧副本能跑，但和上游分叉，每次升级都要手工合代码；
- 正式版对得上上游，但里面只有**示例占位词**，直接跑检索是空的。

迁移之后：**算法在正式版（可以一直升级），你的私有配置在 `config/`（被 `.gitignore` 挡住，
永远不会进 GitHub）**。两边不再分叉。

## 一条命令

```bash
# 先只看它读到了什么，不动任何东西
python tools/migrate_private.py --from <旧副本>/server

# 确认无误再落盘
python tools/migrate_private.py --from <旧副本>/server --write
```

它会搬这五样东西：

| 从旧副本哪里读 | 搬到正式版哪里 | 说明 |
|---|---|---|
| `knowledge.py` 的 `CORPUS_GLOBS` | `config/settings.json` 的 `corpus_globs` | 你的材料还在原地，不用搬文件 |
| `knowledge.py` 的 `DOMAIN_WORDS` | `config/domain_words.txt` | 领域词表 |
| `knowledge.py` 的 `TOPIC_TERMS` | `config/topic_terms.json` | 话题词表（项目名 → 材料加权） |
| `main.py` 的 `MODEL_DIR` | `config/settings.json` 的 `model_dir` | ASR 模型路径 |
| `answer.py` 的 `KEY_FILE` | `config/api_key.txt` | 复制一份密钥（不打印内容） |

> 工具用 AST 读常量，**不会执行旧副本的代码**，副作用为零。默认只报告，`--write` 才写文件。

## 迁移后验证

```bash
python tools/preflight.py
```

期望结果：**FAIL 0**。会真调一次 DeepSeek、真加载一次 ASR 模型、真起一次浮窗。
如果哪一项 FAIL，把它打印的改法照做即可。

还可以单独确认检索质量没变：

```bash
python tools/regress.py          # hit@1 / hit@3 应当和迁移前一致
```

## 迁移后：按公司分包（可选，但推荐）

材料多了会互相抢排名——**实测掺 25% 自己的面试录音，hit@1 从 89.7% 塌到 41.0%**
（详见`配置手册`（见仓库文件 `配置手册`）的「资料包」一节）。所以推荐按面试分包：

```
knowledge/
  _base/            所有面试通用：项目报告、简历、数字卡片……
  字节跳动/          这家公司专用：JD.md、公司介绍.md、一面面经.md……
```

```bash
python tools/profiles.py --new 字节跳动        # 建包（含 company.md 模板）
python tools/profiles.py --check 字节跳动      # 试算：切过去会加载哪些材料
```

然后在 `config/settings.json` 里填 `"corpus_profile": "字节跳动"`，重启后端。
**留空就还是老行为**，不分包也能用。

## 常见问题

**迁完能马上删掉旧副本吗？**
先别删。跑一次 `preflight.py`，再跑一次 `regress.py` 确认数字对得上，观察一两场之后再删。

**`config/settings.json` 会被提交吗？**
不会。它、`config/api_key.txt`、`config/domain_words.txt`、`config/topic_terms.json`
都在 `.gitignore` 里，`git status` 会显示成 `!!`（已忽略）而不是待提交。

**两个副本能同时跑吗？**
不会冲突——它们读各自的 `config/`。但**端口是共享的**（默认 8765 起），
所以同一时间只跑一个后端，否则后起的会自动顺延到 8766，浮窗读 `.runtime_port` 会连错。

**材料还留在原来的目录，要挪进 `knowledge/` 吗？**
不用。`corpus_globs` 指哪读哪。只有想用「按公司分包」时才需要挪。
挪的时候注意**别在原位置留副本**，否则同一份材料会被当成两份，白白稀释排名。
