# EarShot（顺风耳）· 隐私与安全

> 写给真要拿它去面试的人：这份文档只讲两件事——**什么数据离开了你的电脑**，以及**浮窗的「防共享」到底防得住什么、防不住什么**。
> 所有结论都对应代码里的具体做法；没验证过的地方我会明说是推测。

---

## 0. 一句话结论

**音频、识别、检索全程不出本机；只有「生成答案」这一步会把你的问题文本和检索到的材料片段发到 DeepSeek。**

浮窗的「防共享」= `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`，它能保证这个窗口不进屏幕截取/录屏，**防不住摄像头、手机拍屏、采集卡，也不保证某些采集链路上的「共享整个桌面」**。真正的逃生手段永远是 `Ctrl+Shift+H`。

## 2. 会离开本机的（发往 DeepSeek）

一次答案生成请求，发出去的是这四块**文本**：

| # | 内容 | 说明 |
|---|---|---|
| 1 | 面试官提问的**识别文本** | 真人原话的转写，含对方说出的公司名/项目名/技术名 |
| 2 | **检索命中的材料片段**（top-k） | 来自你自己的 `knowledge/`，这才是信息量最大的一块 |
| 3 | `config/company.md` **全文** | 目标公司业务 / JD / 技术栈 / 面试官，每题都带 |
| 4 | **上文 1~2 句** | 上一问、上一答，用来接「那这个呢」这类省略式追问 |

不包含：音频、录音文件、会话日志、浮窗截图、你的密钥（密钥只在 HTTP 请求头里，用于鉴权）。

**所以要下的决策是「哪些材料进 `knowledge/`」，不是「这个工具会不会偷偷上传录音」——它不会。** 材料里如果写着上一家公司的内部业务细节、真实客户名、未公开数字，那这些会随检索片段一起发出去。

深答线（可选，默认关闭）：如果配了 `dsh_node` / `dsh_bin` / `dsh_home`，按深答键时会把问题交给一个 `dsh --profile headless` 子进程，那个会话有自己的工具能力（例如联网搜索），发送范围由那份 profile 的配置决定——**这不是本工具的隐私边界，用之前先想清楚**。

## 3. 全程不出本机的

- **音频**：回环采到的语音从采集到识别都在本进程/本机，一帧都不外发。
- **识别**：本地 SenseVoiceSmall ONNX int8，无 API 调用（这也是它为什么能 100 ms 出结果）。
- **检索**：本地 BM25 + jieba，语料和索引都在磁盘上。
- **浮窗渲染**：本机 Qt 窗口。
- **你自己的声音**：不抓麦克风 → 从未被采集、也从未被转写。

## 4. 日志里存了什么

| 路径 | 内容 | 保留策略 |
|---|---|---|
| `logs/session_<时间戳>.jsonl` | 每场一个文件，每题一条 JSON：`qid` / `q`（问题原文）/ `qtype`（题型）/ `answer`（**答案全文**）/ `firstMs` / `totalMs` / `sources`（命中的材料来源文件名）/ `warns`（数字与经历告警）/ `offline`；被过滤的非提问也记一行；采集异常记 `audio_lost` | 一直留着，**要自己删** |
| `logs/backend_error.log` | 后端线程异常堆栈 | 追加 |
| `logs/launch.log` | 启动编排日志 | 追加 |
| `.tmp/live_*.wav` | **回环采集的音频片段**（约 180 KB/段） | 启动时清理，**只保留最近 20 段** |
| `.runtime_port` / `.ui_pid` | 实际端口 / 浮窗 PID | 覆盖写 |
| `config/terms_review.md` | `tools/build_terms.py` 从材料里抽出的技术名词清单（**可能含公司名与技术栈**） | 生成物，自己删 |
| `config/company.md`、`config/*_terms.md`、`knowledge/` | 你的材料与人工白名单 | 你自己管 |

要点：

1. **`logs/session_*.jsonl` 里有答案全文和问题原文**——它是一份很完整的面试记录，也是很好的复盘资料，但**不要随手把它分享出去**（里面有公司名、项目数字、你的项目细节）。
2. **磁盘上会短暂存在录音片段**（`.tmp/live_*.wav`，每段约 180 KB，只留最近 20 段）。不想留就在面试后手动清空 `.tmp/`。
3. 会话日志**不进 `.gitignore` 之外的任何地方**——它就在本地仓库目录里（`logs/`）。发布仓库时别把 `logs/` 一起打包。

## 5. 密钥保管

| 项 | 现状 |
|---|---|
| 默认位置 | `config/api_key.txt`（**明文文件**，一行密钥） |
| 替代方式 | 环境变量 `TP_API_KEY`（优先级高于配置文件），密钥可以不落盘 |
| 版本控制 | 按配置契约，`config/api_key.txt` 与 `config/settings.json` 都必须在 `.gitignore` 里（**发布前确认仓库里确实有 `.gitignore` 且包含这两条**，缺了就先补上再提交） |
| 自检 | `tools/preflight.py` 第 7 项会检查密钥文件是否存在、是否为空、真调一次能否出首字 |

注意事项：

- 别把工作区同步到公共网盘、共享盘、别的机器；别把密钥截图发出去。
- 别改 `.gitignore` 里的那条规则，也别用 `git add -f` 强推密钥文件。
- 怀疑泄漏：立刻去 DeepSeek 控制台吊销这个 key 并重新签发（换掉 `config/api_key.txt` 即可，不用改代码）。
- 团队/多人共用一台机器时，用 `TP_API_KEY` 环境变量比共享密钥文件干净。

## 6. 防共享：实现了什么，边界在哪

### 6.1 三个「硬需求」分别靠什么实现

| 需求 | 实现 | 实测 |
|---|---|---|
| **置顶**（压过全屏会议窗口） | 窗口标志 `WindowStaysOnTopHint` + `Tool`，并每 2 秒 `SetWindowPos(HWND_TOPMOST)` 保活 | 通过 |
| **屏幕共享/录屏里不可见** | `SetWindowDisplayAffinity(hwnd, WDA_EXCLUDEFROMCAPTURE = 0x11)`（Win10 2004+） | 通过：系统截屏里窗口完全消失 |
| **全局热键不依赖焦点** | `RegisterHotKey` + 原生消息 `WM_HOTKEY` | 通过；首选键被占时自动换成备用组合 |

### 6.2 能防住什么

- **系统截屏**（PrintScreen、截图工具）：窗口不出现在结果里。
- **走 DWM 截取链路的录屏/共享**：典型情况下对方看到的是「没有这个窗口」的画面。
- 这在「面试官让你共享某个窗口」这类场景里是有效的——但**别把它当成安全保证**。

### 6.3 防不住什么（一条都别忽略）

1. **手机 / 相机拍屏**。物理拍摄和软件 API 没关系。
2. **采集卡、部分第三方采集方式**。被采集的是显示输出，不保证遵守这个 API。
3. **「共享整个桌面」的个别采集链路**：可能仍会出现窗口边框或残影（实测覆盖的范围只有系统截屏，其它链路**未逐一验证**）。
4. **对方对你本人的摄像头拍摄**：你的眼神、你的停顿、你瞟屏幕的动作。
5. **面试官念完答案后现场追问细节**：屏幕上挡得住，你的脑子挡不住。
6. **任务栏/Alt-Tab/窗口列表**：它用 `Qt.Tool` 窗口类型（不占任务栏），但置顶窗口在系统 UI 里并非绝对隐形。

### 6.4 逃生手段

`Ctrl+Shift+H` **一键隐藏/显示**（若被占用会自动换成备用键，以浮窗底部提示行为准）。面试官说「能不能共享一下屏幕」的时候，先按它，再回答。

## 7. 音频采集的边界

- **只抓渲染流（系统要播放出去的声音）**：所以用**耳机也照样能抓**（实测默认播放设备就是耳机，回环照样可用）；你自己的声音不会被转写（麦克风那条线完全不碰）。
- **系统提示音、音乐、语音消息也会被抓进去**：这是同一条流的代价。程序有 VAD 语音占比过滤，也可以在面试中按暂停键；会前试回环时顺手关掉会「叮咚」的软件。
- **会议软件用独占模式会抓不到**：把会议软件的音频输出设成共享模式（默认就是）。启动自检里的「回环采集设备存在」和「当前有声音在放」就是查这个。
- **设备变化会中断**：拔插耳机、切换默认播放设备会触发采集重连（退避 1→15 秒一次，每 5 秒检测一次设备变化），期间屏幕会显示「⚠ 音频掉了，正在重连」。

## 8. 使用伦理与合规提醒

这一节不是免责声明，是这个工具的设计前提：

1. **多数公司的面试协议明确禁止使用 AI 代答或外部辅助。** 部分平台会检测异常进程、要求开启录屏或共享整个桌面。用不用、怎么用，是**你自己的判断**，本工具不做任何对抗检测的伪装（见 FAQ 第 21 条）。
2. **它是提词器，不是替考。** 屏幕上出现的每一句话都要你张口说出来，并且要接得住追问。
3. **产品里有三道刻意的「不许编」约束**（这是研发过程中被真实事故逼出来的）：
   - 材料外名词命中时走「坦诚」策略（承认没做过 → 按原理推 → 说能迁移的经验 → 反问对齐术语）；起因是实测里模型两次凭空长出技术经历（eBPF、Temporal 各一段），听起来最专业、追两层就穿帮；
   - 答案生成后的 `check_answer()` 会核对数字与经历出处，对不上就在屏幕上贴红标（**只提示，不拦截**——最终判断权在你）；
   - `config/never_used.md` 让你把「材料里写了但我其实没做过」的东西锚死。
   - **不会**和**不诚实**是两件事：前者是面试常态，后者是直接淘汰项。
4. **别做的事**：把答案念成报纸；把日志/截图发给别人；把密钥和日志同步到公共位置；拿它去考别人。
5. **别拿隐私当赌注**：材料里含上一家公司的内部细节、客户名、未公开数字时，这些会随检索片段发到 DeepSeek。**入 `knowledge/` 之前先过一遍**。

## 9. 依赖与模型从哪来（供应链）

前面几节讲的是「你的数据去哪了」；这一节讲「你装的这些东西本身可信吗」。

EarShot 的代码全在仓库里、可读可审，但它要从外面拿两样东西：**Python 依赖**和 **ASR 模型权重**。这两条下载链路就是唯一的外部输入。

| 拿什么 | 从哪拿 | 怎么保证没被换过 |
|---|---|---|
| 57 个 Python 包 | PyPI（或你指定的镜像） | `requirements.lock.txt` 锁住每个包的 sha256，安装时 pip 逐个核对，对不上就拒绝安装 |
| 6 个 ASR 模型文件 | ModelScope（`iic/SenseVoiceSmall-onnx` + `iic/SenseVoiceSmall`） | `tools\download_model.py` 里写死 sha256，下载完立刻校验，对不上就删掉文件并报错 |

其余的一切都在本机：ASR 推理（ONNX Runtime）、检索（jieba / BM25）、浮窗（PyQt6）都不联网。

**边界，别忽略：**

- 哈希锁保证的是「锁住之后不会再被改」，防不了「锁的那一刻上游就已经是坏的」。
- `jieba` 只发布源码包，装它的时候 pip 会执行它的构建脚本——哈希保证内容没被换过，但构建过程本身会跑代码。
- 不在保护范围内：pip 自身、Python 解释器、Windows 系统组件。
- 模型哈希来自本机那份已验证可用的模型，没有去 ModelScope 官网逐字节核对。

细节与实测数据见 `docs/安装教程.md` 第九节。

## 10. 会前自查（5 条，2 分钟）

1. `git status`（或看仓库文件列表）确认 `config/api_key.txt`、`config/settings.json`、`logs/` 没有进版本库；`.gitignore` 里确实有前两条规则。
2. 确认 `config/api_key.txt` 只有一行密钥；这台机器上没有把工作区同步到别处。
3. 想清楚这场面试有没有「共享整个桌面 / 开摄像头 / 要求录屏」的要求——有的话先按一遍 `Ctrl+Shift+H` 演练。
4. 想一遍：屏幕上可能出现的答案里，哪些是你**接得住追问**的；哪些只是提示。
5. 确认 `Ctrl+Shift+H` 在你这台机器上真的生效（`tools/preflight.py` 第 10 项 + 浮窗底部提示行）。
