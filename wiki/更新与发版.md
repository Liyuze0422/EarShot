# 更新与发版

这一页讲两件事：**用的人怎么升级**，和**维护的人怎么发版**。

## 用的人：程序会自己更新

启动时，「选择知识库」窗口右下角如果出现「有新版本 x.y.z」，点它就能看到这一版改了什么。

- 点「立即更新」→ 程序把差分包下载好、校验完 → **关掉提词器，再重新双击启动**，
  新版本会在启动的那一刻装好。
- 也可以点「打开下载页」去 Releases 手动下全量包。

**为什么要点一次重启**：Windows 锁着正在运行的 exe，程序自己换不掉自己。
所以「立即更新」只是把文件备好，真正的替换发生在**下次启动的第一件事**。

- 更新提示**只出现在选知识库的窗口**。浮窗是面试时用的，任何时候都不会弹更新 ——
  面试进行到一半被打断是不能接受的。
- 网络不通时它只是不提示，不会报错、不影响使用。

### 差分包和全量包

| | 大小 | 什么时候下 |
|---|---|---|
| 差分包 patch-from-vX | 通常几十 MB | 你装的是上一版时 |
| 全量包 win64-full | 约 486MB | 第一次装，或者跨了很多个版本 |

差分包只装**变化的文件**：安装目录里有 1581 个文件，自有代码只有 54 个（0.85MB），
其余是 Python 依赖和运行库 —— 每次发版真正变的通常只有 EarShot.exe 和几个 py 文件。

## 维护的人：一条命令发版

**源码运行的人不需要这套东西**，git pull 就是更新。

装成 exe 的版本这样发：

	# 只检查，不打包
	python tools\release.py --version 0.9.20

	# 门禁 + 打包 + 生成资产
	python tools\release.py --version 0.9.20 --build

	# 再发到 GitHub
	python tools\release.py --version 0.9.20 --build --publish

它会依次做四件事：

1. **门禁**：ruff + pytest + test_repo_hygiene.py（和 CI 同一套，过不了就不打包）
2. **对版本号**：server/version.py 和 CHANGELOG.md 的 ## x.y.z 必须对得上
3. **打包**：PyInstaller → dist\EarShot
4. **出资产**：清单 manifest-vX.json + 全量包 + 差分包（会自动找产物目录里上一版的清单）

发布前先确认 gh 已登录；本机如果需要代理，先设好 HTTPS_PROXY。

### Release 里应该有的三个文件

| 文件 | 作用 |
|---|---|
| EarShot-vX-win64-full.zip | 全量包 |
| EarShot-vX-patch-from-vY.zip | 差分包，**起点版本必须和用户装的一致**，对不上程序会自动改走全量 |
| manifest-vX.json | 文件清单（路径 + 大小 + sha256），差分的依据 |

## 诚实边界

- **CI 自动发版（.github/workflows/release.yml）写了但没跑通过。** 它要在 Windows
  runner 上装 funasr / onnxruntime / PyQt6（上 GB），能不能装成功、会不会超时都没验证。
  现在**实际能用的是本地 tools/release.py**。
- 应用内更新是 0.9.20 才有的。下载 + 校验 + 替换的端到端在本地用假远端完整跑过
  （覆盖 / 新增 / 删除 / 用户自己的文件不动，五项全对），**还没在真实 GitHub 资产上跑过**。
- 没有**代码签名**，Windows SmartScreen 会拦首次运行的 exe。

## 为什么差分只能压到三十几 MB

实测（同一份代码连续打包两次，比对 1589 个文件的字节）：

| 文件 | 两次打包 | 原因 |
|---|---|---|
| EarShot.exe | **不同**（33.13 MB）| PyInstaller 的 PKG 归档里带构建时间戳，不可复现 |
| _internal/base_library.zip | **不同**（1.27 MB）| 同上 |
| 其余 1587 个 | 完全一样 | —— |

结论：**每次发版，差分包里必定包含这两个文件，合计约 34 MB**，这是这套方案的下限。

收益仍然是实在的：全量包 219.5 MB，差分包 33.1 MB，**省 85%**。

想再往下压只有两条路，都没做（要做就得重新验证启动链路）：

1. 把 Python 代码从 exe 里挪到 _internal/（改 spec 的 PYZ 位置），让 exe 只当引导器；
2. 干脆不发 exe，只发源码包（对普通用户不友好）。

另外注意：包内的 release_manifest.json 里有一个 created 时间戳，所以它在两次打包之间
也会不同 —— 这没关系，它本来就不参与清单比对（清单不包含它自己）。

## 出问题了怎么退回

- 替换前会在安装目录留一份 EarShot.exe.bak，新版本起不来可以拿它换回去。
- 差分包只覆盖清单里的官方文件。**你自己放进安装目录的东西既不会被覆盖也不会被删除。**
- 实在不行去 Releases 下全量包，解压覆盖（config/ 和 知识库/ 是你的数据，不在包里，不会被覆盖）。
