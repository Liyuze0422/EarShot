## 1. 先做这三件事

### 1.1 日志地图（logs 目录）

| 文件 | 谁写的 | 什么时候看 |

| `logs/launch.log` | tools/launch.py 启动器 | 启动器判断「后端在不在跑」「等没等到就绪」；每行带 [HH:MM:SS] 时间戳 |

## 2. 安装阶段

| 症状 | 原因 | 处理 |
|---|---|---|
| `setup.ps1` 第 0 步就 FAIL，提示「仓库路径含非 ASCII 字符」 | 仓库放在中文路径下。模型自带的 sentencepiece 是 C++ 实现，遇到中文路径在 C++ 层报 NOT_FOUND，而 Python 侧 os.path.exists() 认为文件存在 | 把仓库移到纯英文路径（推荐 C:\dev\EarShot）；或只把模型放纯英文目录并设 `TP_MODEL_DIR`；或改 `config/settings.json` 的 model_dir |
| 提示「没找到可用的 Python」 | 没装 Python，或没加进 PATH，或只装了 32 位 / 3.13 | 装 64 位 Python 3.12（官网安装时勾 Add python.exe to PATH，或 winget install Python.Python.3.12）；装完**重开 PowerShell**；也可用 -PythonExe 'C:\Python312\python.exe' 指定 |
| 提示「Python 是 32 位的，依赖装不上」 | 装了 32 位解释器 | 换 64 位版本（下载页选 Windows installer (64-bit)） |
| 建 .venv 失败 | 目录没写权限；杀毒软件拦截 | 换到自己的目录（如 C:\dev\EarShot）；把仓库目录加进杀软白名单；删掉残留的 .venv 重跑 |
| pip install 慢 / 超时 / Read timed out | 直连 PyPI 慢 | powershell -ExecutionPolicy Bypass -File `scripts\setup.ps1` -Mirror（清华源）；或 -IndexUrl <你的源>；或先设代理 $env:HTTPS_PROXY = 'http://127.0.0.1:7890' |
| pip 报 No matching distribution found for numpy>=1.26.4 之类 | 解释器版本不在支持范围（例如 3.13 早期版本），或镜像缺包 | 换 Python 3.11 / 3.12；换源重试 |
| pip 报 Errno 13 Permission denied | 文件权限 / 杀软拦写 site-packages | 换目录、关掉杀软实时防护重试、确认 .venv 没被别的进程占用 |
| `download_model.py` 卡住或个别文件 FAIL | ModelScope 网络不通 | 换网络后重跑（已下好的文件会跳过）；或按安装教程 4.3 节的地址手动下载，放进 models\SenseVoiceSmall-onnx\ |
| 模型目录只有 5 个文件 | `download_model.py` 下载的 5 个文件里**不含分词模型** chn_jpn_yue_eng_ko_spectok.bpe.model（它在 iic/SenseVoiceSmall 仓库） | 跑 `setup.ps1` 会自动补；手工装的话按安装教程 4.3 节给的地址下载补齐（约 368KB） |
| 直接跑 `.venv\Scripts\python.exe` 可用，但双击启动脚本报「找不到文件」 | 用编辑器把 .bat / .ps1 存成了 UTF-8 无 BOM（或改了里面的中文），cmd 按 GBK 读走样；PowerShell 5.1 同样会把无 BOM 的 .ps1 当 GBK 读，中文乱码之外还会语法报错（实测 8 处） | 不要改这两个文件里的中文；确需修改时用「UTF-8 带 BOM + CRLF」保存。仓库里的 启动提词器.bat 本身是纯 ASCII 的 |

## 3. 启动阶段

| 症状 | 原因 | 处理 |
|---|---|---|
| 启动器 60 秒后报「后端 60 秒内没起来」，并打印 backend_console.log 的尾部 | 模型还在加载（首次会久一点），或者后端真的崩了 | 看打印出来的尾部内容与 `logs/backend_error.log`；模型缺失 / 路径非 ASCII / 密钥异常都会在这里现形 |
| 启动时说「端口 8765 被占，顺延到 876x」 | 8765 被别的程序占用（或旧后端还在） | **这是设计行为，不用管**：候选端口 `[8765,8766,8767,8768,8769]`，实际端口写进 `.runtime_port`，浮窗每次重连都重读它。要改候选列表就改 `config/settings.json` 的 ports |
| 五个候选端口全被占 | 8765~8769 都被别的程序占了 | 腾一个出来，或改 ports 加端口（例如 [8865,8866]） |
| --check 报「后端在跑」但浮窗没出来 / 浮窗显示**「后端未连接」** | 浮窗先起来了、后端还没 ready；或浮窗连的端口与后端不一致；或浮窗进程崩了 | 1) 先 `.\scripts\run.ps1` --check 看端口，再 Get-Content `.runtime_port` 核对；2) 看 `logs/ui_console.log` 的报错；3) 直接重跑 `.\scripts\run.ps1`（幂等） |
| 起了两套后端 / 屏幕上两块浮窗 | 绕过了启动器手动跑 `server\main.py` / `ui\app.py`，或重复双击 | 先全部停掉（见 3.1），再用 `.\scripts\run.ps1` 启动一次。启动器通过端口探测与 `.ui_pid` 避免重复起 |
| 启动输出一直没有「就绪」 | 后端在等模型加载 / 预热 | 首次启动共约 8 秒（加载 4.0s + 预热 3.8s）属正常；超过 60 秒按上一行处理 |

### 3.1 怎么停干净

```powershell
.\scripts\run.ps1 --stop
```

启动器会清掉 .runtime_port 与 .ui_pid。如果它报告「已停掉 0 个提词器进程」而任务管理器里进程还在，用这条兜底：

> 这个坑在 0.9.21 之前存在：旧版按**进程名**预筛时只认 `python.exe`/`pythonw.exe`，
> 所以「双击过打包版 `EarShot.exe`、又用源码版 `run.ps1 --stop` 去关」会一个都匹配不到 ——
> 但它仍然删掉了 `.runtime_port`，下次启动就会误判「没在跑」而再起一个后端（端口漂到 8766）。
> 现在 exe 名字是无条件认的。

```powershell
Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -match 'server[\\/]main\.py|ui[\\/]app\.py' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
Remove-Item .runtime_port, .ui_pid -ErrorAction SilentlyContinue
```

## 4. 音频：抓不到声音

| 症状 | 原因 | 处理 |
|---|---|---|
| 播放有说话的音频，浮窗底部**电平条不动** | 回环设备打不开 / 默认播放设备不是正在出声的那个 / 会议软件用了独占模式 | 1) 跑设备自检：`.venv\Scripts\python.exe` -X utf8 `tools\check_audio.py`（它打印默认扬声器、能否拿到回环设备、以及全部含 loopback 的采集设备）；2) 把系统默认播放设备设成**正在出声的那个**；3) 会议软件音频设备改回**共享模式**（默认就是，别选独占） |
| check_audio.py 报「取回环设备失败」 | 系统里没有可用的回环设备 | 装好声卡驱动（Realtek 等）后再看列表；VB-Audio Cable 这类虚拟声卡也能作为回环 |
| 电平条动、但转写是空的 | 声音太小 / 段太短 / 都是非语音 | 调大系统音量；看 `logs/backend_console.log` 有没有 ASR 相关行；`preflight.py` 第 2 项会告诉你采样到的 RMS |
| 面试中状态栏红字「音频掉了，正在重连」 | 插拔耳机 / 会议软件改了音频路由 | **别慌，后端在自愈**（每 5 秒检测默认设备变化，退避到 15 秒一次）；恢复前题库仍在兜底。想立刻恢复：把默认播放设备切回原设备 |
| 以为"戴耳机就抓不到" | 误解 | 回环抓的是**渲染流**，戴耳机照样能抓 —— 实测环境默认设备就是耳机，回环可用。抓不到是别的原因，按上面几行查 |
| 转写里出现自己的声音 | 系统里在放你自己的声音（回声 / 你开麦外放） | 程序只抓系统播放流；请用耳机，避免自己的声音被系统播放回来 |
| **提词器只听得见你自己说话，面试官说什么它不知道**（首次使用最容易遇到） | 挑设备时**撞了名字**：Windows 上蓝牙耳机（Hands-Free）的播放端点和录音端点**友好名一模一样**，而 soundcard 按名字查设备时，同名的真麦克风会把回环设备顶掉（0.9.22 已修） | 跑 `.venv\Scripts\python.exe` -X utf8 `tools\check_audio.py` —— 看「旧写法」那一行：如果它拿到的设备 `isloopback=False`，说明这台机器会踩到。升级到 **0.9.22** 即可（新版按 WASAPI id 匹配，id 唯一不会撞名） |

## 5. 识别不准

| 症状 | 原因 | 处理 |
|---|---|---|
| 专有名词被写坏（lara / rog / lmm 这种） | ASR 对低频专名的固有缺陷，转写稿本身也会这么写坏 | 把你会但材料里没写的词写进 `config/known_terms.md`：命中即「不算没准备过」，程序还会把「他说的 X 应该是 Y」写进提示词 |
| 面试官问的词我明明会，屏幕上却标「没准备过的名词」 | 该词在材料里查无此词 | 同上，补 `config/known_terms.md`；散开的字母（m c p）会被归一化拼回，不用手工补这种形态 |
| 反过来：材料里写了、我其实没做过 | 词表回答不了「做没做过」 | 写进 `config/never_used.md`，命中即走「坦诚」话术，不管材料里写了多少 |
| 整句识别成空串 | 段内是静音 / 噪声，或音量太低 | 属正常现象；若真人说话的 wav 也是空串，查模型与设备（`preflight.py` 第 3 项会给 WARN 说明） |
| 数字听错（十二 / 二十） | ASR 数字混淆 | 靠材料里写清楚的数字兜底；答案里的数字会做后校验，材料与上文都没有的数字会在核心框标红警告「数字 xxx 不在本题材料里」 |
| 中文识别很慢（首次） | `numba JIT` 编译 | 见下一节 |

### 5.1 首次识别要 21.7 秒（这是已知的，不是卡死）

**原因**：首次识别含 **numba JIT 编译**，实测 **21.7 秒**；预热之后单次识别只要 80~115 ms（2.4~4.1 s 音频），RTF 0.025~0.03。

**处理**：

- 正常启动时后端会自己做预热（加载 4.0 s + 预热 3.8 s，用 2 秒静音先跑一次），所以**不要绕过启动器**直接跑 server\main.py —— 那样第一题就报废。
- 手工跑 preflight.py（不带 --fast）也会触发首次识别，慢是正常的，之后同样受益。
- 看到浮窗底部显示「加载模型…」「预热中…」就等着，别重复启动。

## 6. 答案不出现 / 答案不对

| 症状 | 原因 | 处理 |
|---|---|---|
| 完全不出答案，浮窗一直是空的 | 没有密钥、密钥无效、额度不足、网络不通 | 跑 `preflight.py` 第 7 项（DeepSeek 快答线）——它真调一次，失败原因写得很直白：密钥 / 网络 / 额度。密钥两种配法见安装教程 4.4 节；Get-Content `config/api_key.txt` 确认文件里只有一行密钥 |
| 不装密钥能不能用 | 可以 | 后端照常启动，快答线退回本地题库；有命中时会铺成「【离线题库】…」。会前跑 tools/build_bank.py 能让兜底更厚 |
| 首字迟迟不来，屏幕上出现「快答线还没出字（网络慢）」 | 超过 `TP_FIRST_WARN`（默认 5 秒）还没吐第一个字 | 这题先自己讲，出字了会自动上屏。网络抖动导致的超时会被 `TP_TIMEOUT`（默认 8 秒）+ `TP_RETRIES`（默认 1 次）兜住，再失败就走题库兜底 |
| 屏幕上出现「快答线失败」 | 断网 / 接口挂了 / 额度耗尽 | 题库里有现成答案会自动铺成「【离线题库】…」；没有就按 Ctrl+Shift+D 手动补一次（深答线，若已配置） |
| 答案慢得离谱（首字好几秒） | 网络抖动；或换成了思考模型 | 确认 `llm_model` 仍是 `deepseek-flash`。实测思考模型（如 deepseek-v4-pro）首字约 6690 ms，面试场景不可用 |
| 答案里出现了材料里没有的数字 | 模型编造（少见），或材料里确实没写 | 核心框会标红「⚠ 数字 xxx 不在本题材料里」——**照念前先确认**：改掉这个数字，或用自己的话讲 |
| 答案跑题到上一个项目 | 话题突然切换时上下文窗口可能把检索拉回旧话题（**已知的主要未解问题**） | 用强话题词说清楚（把项目名说出来）；或按 Ctrl+Shift+E 展开看它命中了哪份材料，判断是不是检索错了 |
| 追问预案不出现 | 本地题库里没有这条问法的变体 | 会前跑 tools/build_bank.py --followup --merge 补追问式问法 |
| 每题都被过滤成「已过滤(非提问)」 | 面试官在调设备 / 自言自语被拦掉了（正常） | 如果是误杀真问题：把那句用 Ctrl+Shift+D 手动补问一次 |

## 7. 浮窗与防共享

| 症状 | 原因 | 处理 |
|---|---|---|
| 浮窗不见了 | 被 Ctrl+Shift+H 隐藏了（这是切换键） | 再按一次 Ctrl+Shift+H |
| 浮窗被全屏会议窗口盖住 | 置顶保活没生效（极少数显卡 / 全屏独占场景） | 让会议软件窗口化（不要独占全屏）；浮窗每 2 秒用 `SetWindowPos`(HWND_TOPMOST) 保活，窗口化场景下稳定 |
| 录屏 / 截图里能看到浮窗 | `SetWindowDisplayAffinity`(..., `WDA_EXCLUDEFROMCAPTURE`) 在某些采集路径下不生效 | 见 7.1 |
| 面试官让你共享屏幕 | 防共享有边界 | **先按 Ctrl+Shift+H**（逃生舱）。窗口本身对截屏 / 录屏隐藏，但「共享整个桌面 / 采集卡 / 放大镜」不保证 |
| 浮窗挡住了别的东西 / 位置不对 | 默认位置不合适 | 拖到摄像头正下方、视线平移就能看到的位置；别放屏幕正中央 |

### 7.1 防共享到底防住了什么

- **防住的**：系统级截屏 / 录屏（WDA_EXCLUDEFROMCAPTURE = 0x11），也就是大多数会议软件「共享窗口 / 共享屏幕」走系统截图那条路时，浮窗不出现在画面里。
- **防不住的**：共享整个桌面时的某些采集方式、外接采集卡、磁吸放大镜，以及对方让你开摄像头后从你眼神里看出来的东西。
- **所以**：逃生手段是 Ctrl+Shift+H，面试前把它按熟。细节与合规提醒见 docs/隐私与安全.md 第 6、8 节。

## 9. 自检（preflight）常见 FAIL

跑 .venv\Scripts\python.exe -X utf8 tools\preflight.py，10 项逐条给结论。常见 FAIL 与含义：

| FAIL 项 | 含义 | 处理 |
|---|---|---|
| 第 1 项 回环采集设备存在 | 打不开回环设备 | 见第 4 节 |
| 第 3 项 ASR 模型加载 + 识别 | 模型目录不存在 / 没有 .onnx 权重 / 加载报错 | 跑 `tools/download_model.py`；核对 6 个文件；确认路径纯 ASCII |
| 第 4 项 BM25 检索索引 | 语料 0 块，或查询零命中 | 往 knowledge\ 放 .md / .txt（或拷 examples\knowledge\*）；或改 `corpus_globs` |
| 第 7 项 DeepSeek 快答线 | 密钥 / 网络 / 额度 | 见第 6 节第一行 |
| 第 8 项 端口 8765 占用 | 8765 被**别的程序**占着 | 关掉占端口的程序，或改 ports（后端本身能顺延，这项是在提醒你这个端口不干净） |
| 第 9 项 浮窗启动 + 截图 | 浮窗进程起不来 / 超时 / 没生成截图 | 看 `logs/ui_console.log`；确认有桌面会话（远程桌面 / 无桌面环境下 Qt 起不来） |

--fast 会跳过第 3 与第 9 项（返回 SKIP），第 10 项也会变成「读不到注册结果，不瞎猜」的 SKIP —— 这不是错，是刻意不猜。

WARN 不影响退出码，但值得看一眼：第 2 项（现在没有声音在放）、第 5 项（词表里有脏行或两表冲突）、第 6 项（题库比材料旧，需要重建）、第 10 项（某组热键被占）。

## 10. 日志位置与怎么看

| 想知道什么 | 看哪里 | 关键词 |
|---|---|---|
| 启动器做了什么判断 | `logs/launch.log` | 后端在跑 / 后端就绪 / 已经有一个后端 / 浮窗已经在跑 |
| 后端起没起来、端口几号、模型加载多久 | `logs/backend_console.log` | 提词器后端启动 / 端口已写入 / warmup / chunks |
| 后端线程里崩了什么（控制台看不到的异常） | `logs/backend_error.log` | 时间戳 + 异常栈 |
| 浮窗报了什么错、热键注册结果 | `logs/ui_console.log` | [hotkey] / selftest |
| 这场面试每题答得怎么样 | `logs/session_*.jsonl` | qid / firstMs / totalMs / hits / warn |
| 赛后复盘（人看的版本） | `logs/report_*.md`（由 tools/session_report.py 生成） | 告警题 / 被切掉的题 / 走了兜底的题 / 慢题 |

.runtime_port 是浮窗与工具找后端的唯一依据：内容就是端口号（例如 8765）。如果你手动改过 ports 或换过后端，注意它会被后端启动时重写。

**隐私提醒**：logs/session_*.jsonl 里存着每场面试的问题与答案，.tmp\live_*.wav 里存着最近 20 段录音。分享日志前先想一下；不需要了就删（见安装教程第 8 节）。

## 11. 面试现场急救顺序

1. **浮窗不见了** → Ctrl+Shift+H（切换键，再按会恢复）。
2. **答案不出来** → 这题先自己讲；同时瞄一眼状态栏是不是「快答线失败」（有题库兜底会自动铺上）。
3. **状态栏红字「音频掉了，正在重连」** → 什么都不用做，后端在自愈；把默认播放设备切回原设备会立刻恢复。
4. **屏幕上出现「快答线还没出字（网络慢）」** → 别等，自己先讲；出字了会自动上屏。
5. **面试官要你共享屏幕** → 先按 Ctrl+Shift+H。
6. **整个链路没反应** → **别在现场修**。先用手机 / 第二台设备顶上，赛后再说（复盘材料都在 logs\ 里，跑不掉）。

## 12. 已知边界（不是 bug，别去修）

- **话题突然切换**时检索可能停在旧话题（已用强话题词加权缓解，不是 100%）。
- **没有实词的追问**（「还有哪些」「占比多少」这类）检索可能命中不到，只能靠题库覆盖。
- **多人混轨**：转写里分不清面试官是在问你还是在问旁边的同事。
- **真实面试音频上的 ASR 准确率没测过**（手上只有转写稿，没有原始录音）。
- **路由 100% 是同一场数据上的拟合值**，换一场面试必然下降，必须重跑 tools/regress.py。
- **材料外名词检测有边界**：中文专名宁可漏报也不误报；known_terms.md / never_used.md 靠人工维护，工具只把候选摊开。
- **字级 bigram 检索是负收益**，默认关闭（server/knowledge.py 注释里有数据）。
- **密钥是明文文件**，别把仓库同步到公共网盘；.gitignore 只能挡住 git。
