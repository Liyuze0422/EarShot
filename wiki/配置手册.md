# 配置手册

EarShot 的配置分三层，优先级从高到低：

1. **环境变量**（临时覆盖、脚本里用）
2. **`config/settings.json`**（本机长期设置，已 gitignore）
3. **代码默认值**（`server/settings.py`）

另外还有三份「你自己的信息」放在 `config/` 下的 Markdown 里（不是 JSON 配置，是给模型的上下文）。

---

## 一、`config/settings.json`

模板见 `config/settings.example.json`，复制一份改名即可：

```powershell
Copy-Item config\settings.example.json config\settings.json
```

| 键 | 默认值 | 说明 |
|---|---|---|
| `model_dir` | `<仓库>/models/SenseVoiceSmall-onnx` | ASR 模型目录。**必须是不含中文的绝对路径**，否则 sentencepiece 会在 C++ 层报 `NOT_FOUND` |
| `api_key_file` | `<仓库>/config/api_key.txt` | DeepSeek 密钥文件（文件内容就是密钥本身，首尾空白会被去掉） |
| `base_url` | `https://api.deepseek.com` | 任何 OpenAI 兼容端点都可以填这里（想全本地就指向 llama.cpp / vLLM 的 `/v1`） |
| `llm_model` | `deepseek-flash` | 答案生成模型。**不要用思考型模型**：实测首字 6690ms，面试场景不可用 |
| `corpus_globs` | `["<仓库>/knowledge/**/*.md", "<仓库>/knowledge/**/*.txt"]` | 知识库语料的 glob 列表，可以指向任意目录 |
| `ports` | `[8765, 8766, 8767, 8768, 8769]` | 后端监听端口，被占自动顺延，实际端口写进 `.runtime_port` 供浮窗读取 |
| `dsh_node` / `dsh_bin` / `dsh_home` | 空 | 深答线（可选）：一个能带工具回答的外部 agent 命令。三项都留空则深答功能自动关闭 |
| `vad_end_ms` | `600` | **判停**：静音超过这么多毫秒就认为一句话说完。调到 350~400 实测能让答案早约 200ms 出现，代价是语速慢、爱停顿的人会被切成两句（检索质量下降） |
| `core_max_chars` | `40` | 核心句超过这个字数就标黄 + 缩字号（一秒念不完，实测这类念法合规率只有 79%）。20~60 之间调 |
| `core_font_px` | `20` | 核心大字基准字号（像素）。屏幕小调小、视力吃紧调大 |

### 深答线怎么配（可选）

深答线 = 按 `Ctrl+Shift+D` 之后，让 **DeepSeek Harness 本体带工具**再答一遍，
输出【思路】/【拆解】/【落点】三段，塞进浮窗下面折叠的「深度补充」区。
它跟快答线**并行**跑，不挡快答。

**迟先是实测过的**：真实问题 **39.1 秒**，其中 **11.6 秒是 DSH 启动的固定开销**
（让它只回两个字也要 11.6s），剩下约 27 秒是生成。所以别指望它当主答案用 ——
它是"面试官还在追问、你有半分钟"时的那层补充。

#### 三个路径怎么找

不用猜，从**已经在跑的 DSH 进程**里直接读出来：

```powershell
Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
  Where-Object { $_.CommandLine -match 'bin\.js' } |
  Select-Object -First 1 -ExpandProperty CommandLine
```

输出长这样（`--profile` 后面那段是它自己在用的 profile）：

```
D:\你的node\node.exe C:\你的dsh\data\profiles\node_modules\@deepseek-ai\dsh\lib\bin.js --profile web ...
```

- 第一个路径 = **node.exe 的全路径** → `dsh_node`
- `bin.js` 前那一整段 = **dsh 命令行入口** → `dsh_bin`
- `DSH_HOME` 就是**装着 `profiles\` 的那个目录**（通常以 `.dsh` 结尾）→ `dsh_home`

写成 `config/settings.json`（把下面换成你自己命令行里读出来的）：

```json
{
  "dsh_node": "D:\\你的node\\node.exe",
  "dsh_bin":  "C:\\你的dsh\\data\\profiles\\node_modules\\@deepseek-ai\\dsh\\lib\\bin.js",
  "dsh_home": "C:\\你的dsh\\data"
}
```

**注意 JSON 里的反斜杠要写两个**（`\\`）。三个路径少填任何一个 = 深答线静默关闭，
按 `Ctrl+Shift+D` 只会显示"未配置"。

#### 自检

```powershell
python server\deep.py "如果让你为一家跨境电商公司设计智能客服 Agent，你会怎么搭？"
```

能打印出三段结构 + `exit=0` 就算通了。想单独看固定开销，把问题换成
"你好，只回复两个字：收到"，正常应该在 **11~13 秒**；如果这个都跑不动，
说明是路径或 DSH_HOME 的问题，跟模型无关。

### 手感参数怎么调

上面最后三个是**手感参数**，都有安全默认值，不写就是现在的手感。改完**重启后端 + 浮窗**生效（配置在启动时读一次）。三个的取舍：

| 想要的效果 | 改哪个 | 代价 |
|---|---|---|
| 答案出得更快 | `vad_end_ms` 600 → **350~400** | 停顿多的人会被切句，一句变两句 |
| 屏幕上多放几个字 | `core_font_px` 20 → **16~18** | 瞟一眼的辨认速度变慢 |
| 别再让我念长句 | `core_max_chars` 40 → **25~30** | 信息量少的题答案会更短 |

> 这三个参数**浮窗和后端读的是同一份** `config/settings.json`（`ui/app.py` 直接 import `server/settings.py`），
> 不会出现「浮窗一套默认值、后端另一套」的错位。

## 二、环境变量

| 变量 | 等价于 |
|---|---|
| `TP_MODEL_DIR` | `model_dir` |
| `TP_KEY_FILE` | `api_key_file` |
| `TP_API_KEY` | 直接给密钥（优先级最高，适合 CI / 临时换 key） |
| `TP_BASE_URL` | `base_url` |
| `TP_LLM_MODEL` | `llm_model` |
| `TP_CORPUS_GLOBS` | `corpus_globs`（多个用分号 `;` 分隔） |
| `TP_PORTS` | `ports`（逗号分隔） |
| `TP_DSH_NODE` / `TP_DSH_BIN` / `TP_DSH_HOME` | 深答线三项 |
| `TP_TIMEOUT` | 快答线超时秒数，默认 `8`（面试里没人等得起更长） |
| `TP_RETRIES` | 快答线重试次数，默认 `1`（失败就走题库兜底） |
| `TP_FIRST_WARN` | 首字看门狗阈值秒数，默认 `5`：超过就提示「这题自己先讲」 |
| `TP_SHOT_AFTER` | 浮窗启动 N 秒后自动截图（自检用） |
| `TP_NO_WS` | 自检用：不连后端，只渲染假数据 |

示例：

```powershell
$env:TP_MODEL_DIR = "D:\asr\SenseVoiceSmall-onnx"
$env:TP_TIMEOUT = "6"
python tools\launch.py
```

## 三、三份「你自己的信息」（config/*.md）

这三份不是配置项，而是**每次提问都会带进模型上下文**的材料。

| 文件 | 什么时候用 | 写法 |
|---|---|---|
| `config/company.md` | 每题都带 | 公司业务、JD 关键要求、技术栈线索、面试轮次、你想强调的匹配点。**填得越具体，设计题越贴业务** |
| `config/known_terms.md` | 判断「这个词我到底会不会」 | 一行一个（空格/逗号/顿号分隔）。你会的技术都写进来，提词器就不会让你对它们说「没接触过」 |
| `config/never_used.md` | 同上，反向 | 材料里被顺带提到、但你其实没做过的东西。命中就判**缺口题**，走五段模板【实话】【对比】【展开】【什么时候用】【反问】，不管材料里写了多少 |

### `config/never_used.md` 值得单独说一句

它是"**我知道、但我没做过**"这条线的开关。不填的话，面试官问 CLIP / 多模态 /
语义分割这类，答案是经历题模板（"了解，但项目里用得不多"）—— 听着像敷衍；
填了才会变成：

> 没落到项目里，但原理我清楚 —— ……（一句带过，不停在自我否定上）
> 我这条线用的是 TF-IDF 加向量混合检索，约束是纯文本、离线环境，**输入里没有图像，所以用不上它**
> 我那套具体是……（讲自己的做法，带数字）
> 输入里出现图像、图纸、视频时，才值得加进来

> **别照着 `tools/build_terms.py` 的表格硬抄**：那份表 246 行，一半是噪音
> （`def` / `len` / `try` / `import` / `round2` 这种代码词），照抄只会污染判据。
> 实测有效的挑法是**从被问住过的问题反推** —— 翻 `logs/session_*.jsonl`，
> 找面试官问到、屏幕上却只回了"没接触过"的方向，**一个方向一批词**地填；
> 拿不准的先写在注释里别填（你其实会的技术被说成"没落到项目里"，比"没准备过"更糟）。
>
> 填完**必须验**（30 秒，别跳过）：
>
> ```powershell
> python tools\test_gap_fp.py    # 期望：误报 0，硬案例全中
> python tools\regress.py        # 期望：9 项全过，数值不变
> python server\answer.py "你了解多模态大模型吗？"   # 期望：五段缺口模板
> ```
>
> 只要 `test_gap_fp.py` 的误报还是 0，就说明没伤到"不该判缺口"那道守门员。
> 完整填法（含怎么挑词、填与不填的差别）见 `config/never_used.example.md`。
> 改完要重启提词器才生效。

> 词表怎么生成：`python tools/build_terms.py` 会把材料里出现过的技术名词列成表格。
> 它适合**核对**（"这个词我到底会不会"），不适合直接抄成清单 —— 见上面的说明。

### 另外两份「只属于你」的词表（`config/domain_words.txt` / `config/topic_terms.json`）

这两份不是给模型看的，是给**检索**用的，同样被 `.gitignore` 挡住：

| 文件 | 作用 | 写法 |
|---|---|---|
| `config/domain_words.txt` | 钉住会被 jieba 切碎的专业词（`工作流`→`工作/流` 这种） | 一行一个词；`#` 开头是注释 |
| `config/topic_terms.json` | 判断「这句话在问哪个项目」，命中的材料加权 3 倍 | `{"项目1": ["无人机","地面站",…], "项目2": [...]}` |

模板见 `config/domain_words.example.txt` 与 `config/topic_terms.example.json`。
**不填也能跑**，只是用内置的示例占位词 —— 但那份是给公开仓库用的，基本不匹配你的项目。

> 从旧副本搬过来：`python tools/migrate_private.py --from <旧副本>/server`（先只报告，
> 确认后加 `--write`）。搬完你的真实词表就在 config/ 里，算法留在仓库版，
> 以后升级只维护一份代码。

## 四、知识库（`knowledge/`）

- 默认读取 `knowledge/**/*.md` 与 `knowledge/**/*.txt`，可在 `corpus_globs` 里改；
- 内容会被切成 300~700 字的块，**文件名会加权参与检索打分**，所以文件名取清楚些（如 `项目A_推荐系统.md`）；
- 数字、指标写进句子里，别只放表格；小标题写成人话，更容易和面试官的口语提问对上；
- 这个目录默认被 `.gitignore` 忽略，你的简历与项目材料不会被推到 GitHub。

### 资料包：按公司把材料切开（`corpus_profile`）

面试哪家公司，就用哪家的材料。目录这么放：

```
knowledge/
  _base/            所有面试通用：项目报告、简历、数字卡片……
  字节跳动/          这家公司的：JD.md、公司介绍.md、一面面经.md……
  某创业公司/         company.md（公司背景）+ JD.md
```

然后在 `config/settings.json` 里填 `"corpus_profile": "字节跳动"`（或设环境变量
`TP_CORPUS_PROFILE=字节跳动`），**重启后端**。此后检索只在 `_base/` + 该包范围内做。

管理命令：

```bash
python tools/profiles.py --list            # 有哪些包、各多少字
python tools/profiles.py --new 字节跳动      # 建包（含 company.md 模板）
python tools/profiles.py --check 字节跳动    # 试算：切过去会加载哪些材料
python tools/profiles.py --show            # 当前生效的包和实际语料范围

# 换包用这个（推荐入口）：一次做完配置 + 题库 + 扩展词 + 自检 + 重启
python tools/switch.py --list              # 有哪些包、当前用哪个
python tools/switch.py 字节跳动             # 一键切过去
python tools/switch.py 字节跳动 --check      # 预演，不写任何东西
```

**日常不用记这些命令。** 双击 `启动提词器.bat` 会先弹一个「选择知识库」窗口（`ui/library.py`）：
左边列出已有那些库、每个库多少材料、题库备好没有；选一个，点右下角「开始 ▶」，窗口自己关掉，
接着才起后端和浮窗。没有的库点「＋ 新建知识库」现建一个：起个库名，选**专属文档**（这家公司的材料），
再选**其他 / 补充文档**（简历、项目报告这种所有场次都用的，进共用的 `_base/`）——
`.md` / `.txt` 直接收，**`.docx` 会自动转成 markdown**（纯标准库），还能顺手填一句公司背景。

几个约定：

- `corpus_profile` **留空 = 老行为**（扫整个 `knowledge/`），升上来不会改变任何现有行为；
- 包里的 `company.md` 会当成「公司背景」注入提示词，**同时也会被检索**；
  `config/company.md` 仍然优先级更高（想临时覆盖就用它）；
- 文件名以 `_` 开头的材料**不参与检索** —— 放笔记、待办、草稿可以这么命名；
- 包名写错或目录还没建时，后端启动会打印提示，不会静默少材料；
- **换包别手改配置再记流程，用 `tools/switch.py`**：它把「改 `corpus_profile` → 重建题库 →
  补换说法扩展词 → 自检 → 重启」一次做完，并且会**串场扫描** —— 在 `_base/` 里找别的包留下的痕迹；
- **题库按包分文件**（`知识库/题库_<包名>.json`）：跑过的包切回来**直接复用**，不用重建。
  重建默认 `--merge`（并入旧题库），因为覆盖式重建会让题库**变小** ——
  而题库一小，追问预案就哑了（它要求同一章节命中 ≥2 条），症状看着像代码坏了、其实只是题库缩水；
- 想让公司介绍**跟着包走**，就别留着 `config/company.md`（它优先级更高、会遮蔽包里的那份）：
  `python tools/switch.py <包名> --take-company` 会把它改名成 `.bak` 让包接管。

**为什么必须切开**（实测，`DEFAULT_TOPK=3`，任何外来块挤进前三都会把正确材料顶出去）：

| 往 338 块的知识库里掺 +25% | hit@1 | hit@3 |
|---|---|---|
| 不掺 | 89.7% | 94.9% |
| 掺异题材文档（JD/公司介绍这类） | 87.2% | 94.9% |
| 掺别人的面试录音 | 84.6% | 89.7% |
| **掺自己的面试录音** | **41.0%** | 87.2% |

结论：**参考资料（JD、公司介绍）可以放心多放**，纯规模几乎不影响准确率（掺 2 倍异题材
只掉 2.5）；真正致命的是「讲同一批话题的文本」——尤其是自己的面试录音，用口语反复讲
同一批项目，会把精心写过的材料块整片挤掉。别人的面试录音虽然只掉 5 个点，但它**没有正面
价值**（不是你的经历），所以也别放进知识库——它的正确用途是当回归测试集。

## 五、运行期文件

| 路径 | 作用 |
|---|---|
| `.runtime_port` | 后端实际监听的端口（浮窗每次重连都重新读一遍） |
| `.ui_pid` | 浮窗 PID，启动器靠它判断「是不是已经开了一个」 |
| `logs/launch.log` | 启动器日志（谁先起、健康检查结果） |
| `logs/backend_console.log` | 后端标准输出 |
| `logs/backend_error.log` | 线程里抛出的异常（不会打到控制台的那些） |
| `logs/session_*.jsonl` | 每场会话的完整记录：转写、答案、耗时 —— 赛后复盘与做测试集都从这里来 |
| `.tmp/` | 保留最近 20 段录音（用于排查），会自动清理 |
