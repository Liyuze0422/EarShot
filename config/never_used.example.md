# 材料里出现过、但我其实没做过的东西（提词器专用）

> 这份是随仓库发布的**模板**（`config/never_used.example.md`）。用法：复制成同目录的
> `config/never_used.md` 再往里加词 —— 那份被 `.gitignore` 忽略，属于你本机。
> 程序找不到 `never_used.md` 时会退回读这份模板，所以**不改也能跑**。
>
> **本文件的写法有讲究**：只有「一行一个词」的那些行会被读成词条。
> `#` 注释、`>` 引用、`-` 列表、`|` 表格、成对反引号围起来的代码块，都会被整段跳过 ——
> 所以说明文字尽管写，不会污染判据。（这一条是踩过坑才加的：早先这段说明
> 被拆成 58 个词条，「python」混了进去，谁问「python 你熟吗」都会被判成「我没做过」。）

## 填与不填，差在哪

> 命中这里的词 → 这题判成**缺口题**，走专属模板（五段，直接能念）：

| 段 | 写什么 |
|---|---|
| 【实话】 | 没落到项目里（一句带过，**不许停在自我否定上**）+ 我了解到的原理 |
| 【对比】 | 我这条线用的是 XX、当时的约束是…；**我这个场景为什么现在不需要它** |
| 【展开】 | 把我自己那条线讲具体（唯一允许讲细节的地方，但不许展开面试官问的那项技术） |
| 【什么时候用】 | 什么条件下值得把它加进来 |
| 【反问】 | 一句对齐术语的问题 |

> 同一句「你了解多模态大模型吗？」：
>
> - **不填** → 走经历题模板，答案是「了解，但项目里用得不多……」—— 没有对比、没有适用条件。
> - **填了** → 上面那五段，从「我没落地过」一直讲到「什么条件才该上」，全程不编经历。

## 怎么挑词（别照着 build_terms.py 的表格硬抄）

> `tools/build_terms.py` 会列出材料里出现过的技术名词，但它**一半是噪音**
> （`def` / `len` / `try` / `import` / `round2` 这种代码词），照抄只会污染判据。
> 实测有效的顺序是这三步：
>
> - **从「被问住过的问题」反推** —— 翻 `logs/session_*.jsonl`，找面试官问到、
>   屏幕上却只回了「没接触过 / 不清楚」的方向。那才是真正该填的。
> - **一个方向一批词** —— 比如「多模态」这一族一起填（多模态 / 视觉语言模型 / VLM /
>   CLIP / Qwen-VL / 图像理解），别东一个西一个。
> - **拿不准的先别填** —— 写在文件最底部的注释里。填错的代价比不填大：
>   你其实会的技术被说成「没落到项目里」，比「没准备过」更糟。

## 填完必须验（约 30 秒）

```powershell
python tools\test_gap_fp.py    # 期望：gap 判据全部通过（误报 0，硬案例全中）
python tools\regress.py        # 期望：9 项全过，数值不变

python server\answer.py "你了解多模态大模型吗？"   # 换成你刚填的词
# 期望：输出是【实话】【对比】【展开】【什么时候用】【反问】五段
```

> **只要 `test_gap_fp.py` 的误报还是 0，就说明没伤到「不该判缺口」那道守门员，随便加。**
> 那个脚本里有一节叫「不许判 gap（我会的 / 不是专名）」，列的就是反向清单 ——
> 你要是发现自己会的词被判成了缺口，就是从那儿看出来的。
>
> 改完要重启提词器才生效：先 `powershell -File scripts\run.ps1 --stop`，再起。
