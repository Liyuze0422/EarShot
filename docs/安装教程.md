# EarShot（顺风耳）· 安装教程

> 这份文档带你从一台干净的 Windows 电脑走到「浮窗跑起来、答案能上屏」。
> 每一步都写清楚 **在哪个目录、敲什么、看到什么算成功**。
> 装完想直接用，看 `docs/使用说明书.md`；出问题看 `docs/故障排查.md`。
>
> 本文的命令都在仓库根目录（下称 **仓库根**）下执行。仓库根 = 包含 `server\`、`ui\`、`tools\` 的那个目录。

---

## 〇、先认识它（30 秒）

EarShot 是一个**实时面试提词器**：把面试官的声音转成文字，在 1.3~1.5 秒内把一份「可以照念」的口语答案显示在一块置顶浮窗上。

数据流是这样的：

```
会议软件（腾讯会议 / 飞书 / 牛客 / 网页）
        │  声音从扬声器或耳机播放
        ▼
   WASAPI 回环采集（只抓「系统播放的声音」= 只有面试官，不碰麦克风）
        ▼
   能量 VAD 判停（600ms 静音收句）
        ▼
   SenseVoiceSmall ONNX int8 本地识别（80~115ms / 句）
        ▼
   BM25 + jieba 本地检索你自己的材料（0~1ms）
        ▼
   DeepSeek deepseek-flash 流式生成答案（首字 281~831ms）
        ▼
   PyQt6 浮窗（置顶 / 防共享 / 全局热键）
```

关键点提前说清楚：

- **回环抓的是渲染流**，也就是「系统要播放出去的声音」，所以**戴耳机也照样抓得到**，不需要外放。
- **麦克风那条线完全不碰** —— 你自己的声音永远不会被转写，也不需要做声纹分离。
- **音频、识别、检索全在本机**；只有生成答案时，才会把「问题 + 检索到的材料片段」发到 DeepSeek。细节见 `docs/隐私与安全.md`。

同时也要先知道它的**诚实边界**（这些不是 bug，别当成待修项）：

- 材料里没写过的专有名词，它走「坦诚」话术（承认没做过 + 按原理推 + 反问对齐），**不编造经历**。
- ASR 会把专有名词写坏（实测 `lara` 其实是 LoRA、`rog` 其实是 ROS 这类）。靠 `config/known_terms.md` 的词表兜。
- 字级 bigram 检索通道实测是**负收益**，默认关闭。
- 话题突然切换时，检索可能还停在旧话题上 —— 这是目前**主要未解问题**。
- 多数公司的面试协议**明确禁止**使用 AI 代答。请把它当提词器用（提醒自己的数字与话术结构），不要照读自己接不住追问的内容。见 `docs/隐私与安全.md` 第 8 节。

## 一、系统前提

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | **Windows 10 / 11（x64）** | 回环采集走 WASAPI，Windows 专用；macOS / Linux 未支持 |
| Python | **3.11 或 3.12（64 位）** | `pyproject.toml` 要求 `>=3.11`；CI 跑 3.11 / 3.12；实测环境为 3.12.5。3.13 未验证 |
| 磁盘 | 约 **1.5 GB** 空闲 | ASR 模型 230 MB + venv（含 Qt、onnxruntime 等轮子） |
| 网络 | 首次安装需要；之后**只在生成答案时**需要 | 装依赖、下模型要联网；面试中要能访问 `api.deepseek.com` |
| DeepSeek 密钥 | **可选** | 没有也能启动，快答线会退回本地题库；建议配一个 |
| 显卡 | **不需要** | int8 ONNX 模型跑 CPU，实测进程内存约 491 MB |
| 音频设备 | 任意默认播放设备（耳机或扬声器都行） | 会议软件的音频设备用**共享模式**（默认就是），独占模式抓不到 |
| 麦克风 | **不需要** | 程序不打开麦克风 |

> 内存实测约 491 MB，比方案里预估的 800~1200 MB 好一倍；准确率与延迟数据见 `docs/性能实测.md`。

## 二、第 0 步：把仓库放到纯英文路径

**这一步不能跳过。** 建议路径：`C:\dev\EarShot`。

### 为什么

模型目录里有个 `chn_jpn_yue_eng_ko_spectok.bpe.model`，加载它的是 **sentencepiece 的 C++ 实现**。路径里只要有一个非 ASCII 字符（中文、日文、重音字母都算），它会在 C++ 层直接报：

```
NOT_FOUND: No such file or directory
```

而 Python 这一侧的 `os.path.exists()` 偏偏认为文件是存在的 —— **报错完全指不到真正的原因**。这是本项目踩过的最贵的一个坑，所以 `server/settings.py` 的 `ensure_ascii()` 宁可在启动时就明确拒绝，并打印改法。

### 怎么检查

在 PowerShell 里跑（把路径换成你的实际路径）：

```powershell
# 有输出 = 含非 ASCII 字符，必须换路径；没有任何输出 = 合格
'C:\dev\EarShot'.ToCharArray() | Where-Object { [int]$_ -gt 127 }
```

或者用 Python：

```powershell
py -3.12 -c "import sys; p=r'C:\dev\EarShot'; print('OK' if p.isascii() else '路径含非 ASCII 字符')"
```

### 如果启动时看到这个报错

```
RuntimeError: 路径里含非 ASCII 字符（……），ASR 模型加载会失败。
```

改法三选一（任选一条即可）：

1. **把整个仓库移到纯英文路径**（最省事），例如 `C:\dev\EarShot`。
2. **只把模型放纯英文目录**，用环境变量指过去：

   ```powershell
   setx TP_MODEL_DIR D:\models\SenseVoiceSmall-onnx      # 永久（重开终端生效）
   $env:TP_MODEL_DIR = 'D:\models\SenseVoiceSmall-onnx'  # 仅当前窗口
   ```

3. **改 `config/settings.json` 的 `model_dir`**（把 `config/settings.example.json` 复制成 `config/settings.json` 再改）。

> 仓库路径纯英文是最稳的做法。只把模型挪走也行，但 `models\`、`.tmp\`、`logs\` 这些目录还是会在中文路径下 —— 日志里出现中文路径没问题，模型那条路才是致命的。

## 三、一键安装（推荐）

### 怎么做

1. 把仓库解压 / 克隆到纯英文路径，例如 `C:\dev\EarShot`。
2. 打开 PowerShell，`cd` 到仓库根。
3. 跑：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1
```

国内网络建议加镜像（PyPI 走清华源，快很多）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1 -Mirror
```

### 脚本做什么（6 步，任何一步失败就停下来并给出修复提示）

| 步 | 做什么 | 看到什么算成功 |
|---|---|---|
| 0 | 检查仓库路径是否纯 ASCII | `OK   路径纯 ASCII，可以继续` |
| 1 | 找 Python 3.11 / 3.12（64 位），依次试 `py -3.12` → `py -3.11` → `python` | `OK   Python 3.12.5  64 位  …` |
| 2 | 建 `.venv`（已存在就跳过） | `OK   .venv 已存在，跳过创建` |
| 3 | 装依赖：`pip install -r requirements.txt` | 最后一行 `OK   依赖装好了` |
| 4 | 下 ASR 模型（约 230MB，ModelScope），并核对 6 个文件 | `OK   6 个文件齐全` |
| 5 | 生成 `config\settings.json` / `api_key.txt` / 三份 `*.md`，知识库为空时拷入示例材料 | 每个文件一行 `OK` |
| 6 | 跑 `tools/preflight.py` 全链路自检（10 项） | 结尾 `安装完成，自检没有 FAIL。` |

**脚本是幂等的**：重复运行不会破坏已有环境 —— `.venv`、模型、`config` 下已存在的文件一律保留不动。中途失败修好后直接重跑同一个命令。

### 常用参数

| 参数 | 作用 |
|---|---|
| `-Mirror` | 用清华 PyPI 镜像装依赖 |
| `-IndexUrl <url>` | 自定义 PyPI 源 |
| `-SkipDeps` | 跳过依赖安装（你自己管依赖时） |
| `-SkipModel` | 跳过模型下载（已经下过、或想自己放模型） |
| `-SkipPreflight` | 跳过最后的自检 |
| `-Fast` | 自检用 `--fast`（跳过 ASR 识别与浮窗自检，约 20 秒内） |
| `-PythonExe <path>` | 指定解释器，例如 `-PythonExe 'C:\Python312\python.exe'` |

### 结尾输出长这样

```
====================================================================
  安装完成，自检没有 FAIL。
====================================================================

接下来：
  1. 填密钥    config\api_key.txt（一行，只放密钥本身）
  2. 放材料    knowledge\ 下放你的简历 / 项目报告（.md / .txt）
  3. 会前配置  config\company.md + known_terms.md + never_used.md
  4. 复查自检  .\.venv\Scripts\python.exe -X utf8 tools\preflight.py --fast
  5. 启动      .\scripts\run.ps1
```

> 自检报 FAIL 也别慌：最常见的就是「还没填密钥」。按提示补齐后只跑第 4 步复查即可。

## 四、手工安装（和一键脚本等价的 7 步）

想自己控制每一步、或者一键脚本在某一步卡住了，就按下面走。

### 4.1 建虚拟环境

在**仓库根**执行：

```powershell
py -3.12 -m venv .venv
# 没有 py 启动器就用： python -m venv .venv
```

成功标志：出现 `.venv\Scripts\python.exe`。

```powershell
.\.venv\Scripts\python.exe -V        # 应输出 Python 3.12.x
```

### 4.2 装依赖

```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

国内镜像（任选一种）：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
# 或者先设代理
$env:HTTPS_PROXY = 'http://127.0.0.1:7890'
```

`requirements.txt` 里是**直接依赖**（fastapi / uvicorn / soundcard / soundfile / numpy / funasr_onnx / jieba / openai / PyQt6 / websockets），传递依赖交给 pip 解析。成功标志：没有 `ERROR`，最后一行是 `Successfully installed …`。

> 版本下限就是本机实测通过的版本。`numpy` 那条特意留了注释：**numpy 2.x 未在实测环境验证**，所以下限写的是 1.26.4。

### 4.3 下载 ASR 模型（约 230 MB）

```powershell
.\.venv\Scripts\python.exe -X utf8 tools\download_model.py
```

它从 ModelScope 的 `iic/SenseVoiceSmall-onnx` 仓库下载 5 个文件到 `models\SenseVoiceSmall-onnx\`，并打印每个文件的进度与 MB/s。

**下完必须核对 6 个文件**（少任何一个都会在加载模型时报错）：

| 文件 | 大小 | 来源 |
|---|---|---|
| `model_quant.onnx` | 约 230 MB | `tools\download_model.py` |
| `tokens.json` | 约 0.3 MB | 同上 |
| `am.mvn` | 很小 | 同上 |
| `config.yaml` | 很小 | 同上 |
| `configuration.json` | 很小 | 同上 |
| `chn_jpn_yue_eng_ko_spectok.bpe.model` | 约 368 KB | **另一个仓库** `iic/SenseVoiceSmall`，`download_model.py` 不管它 |

核对命令：

```powershell
Get-ChildItem .\models\SenseVoiceSmall-onnx | ForEach-Object { '{0,9:N1} MB  {1}' -f ($_.Length/1MB), $_.Name }
```

如果缺分词模型，用浏览器打开下面这个地址下载，放进 `models\SenseVoiceSmall-onnx\`：

```
https://www.modelscope.cn/api/v1/models/iic/SenseVoiceSmall/repo?Revision=master&FilePath=chn_jpn_yue_eng_ko_spectok.bpe.model
```

> `scripts\setup.ps1` 会自动帮你补这一个文件；手工装的话别漏了它。

### 4.4 配置 DeepSeek 密钥

两种方式，**任选一种**（两处都有时环境变量优先）：

**方式 A：写进文件（推荐，长期用）**

把 `config\api_key.example.txt` 复制成 `config\api_key.txt`，把你的密钥**单独写一行**进去：

```powershell
Copy-Item config\api_key.example.txt config\api_key.txt
notepad config\api_key.txt
```

规则：只放密钥本身，不要引号、不要分号、不要前后空格；`#` 开头的行会被忽略；文件存成 UTF-8（带不带 BOM 都行，程序按 `utf-8-sig` 读）。想放到别处也可以，改 `config/settings.json` 的 `api_key_file` 或设 `TP_KEY_FILE`。

**方式 B：环境变量（临时用最方便）**

```powershell
$env:TP_API_KEY = '你的密钥'          # 仅当前窗口
setx TP_API_KEY '你的密钥'            # 永久（重开终端生效）
```

密钥申请：https://platform.deepseek.com → API keys。

**别提交到 git**：`config/api_key.txt` 与 `config/settings.json` 都已经在 `.gitignore` 里；仓库还有 `tests/test_repo_hygiene.py`，CI 会扫「疑似 API Key」的字符串，误提交会在 CI 阶段被拦下。

> **没有密钥也能跑**：后端照常启动，快答线退回本地题库（题库里有现成答案时仍然可用），只是不再现生成答案。

### 4.5 准备知识库（`knowledge\`）

检索**只在你自己的材料里找**，所以这个目录里放什么，直接决定面试时屏幕上会出现什么。

- 支持格式：`.md`、`.txt`（默认 glob 见 `config/settings.example.json` 的 `corpus_globs`）。
- 放什么：简历、项目报告 / 复盘（一个项目一个文件）、自我介绍稿、HR 常见问题准备稿。
- 组织建议（更详细的在 `knowledge\README.md`）：
  - **文件名写全**（例如 `项目A_推荐系统.md`）—— 文件名会加权 4 倍参与检索，而口语提问里常常只出现项目名。
  - 数字、指标**写进句子里**，不要只放表格 —— 检索按句子匹配，散落的数字很难被召回。
  - 小标题写成人话（「为什么用行为树」），更容易和面试官的口语提问对上。
  - 别放十万字的原始文档：精炼比量大重要。

**最小例子**：第一次装可以先拿仓库自带的虚构示例把链路跑通（`scripts\setup.ps1` 在 `knowledge\` 为空时会自动做这件事）：

```powershell
Copy-Item examples\knowledge\* knowledge\
.\.venv\Scripts\python.exe -X utf8 tools\preflight.py --fast   # 复查第 4 项「BM25 检索索引」
```

跑通之后**把示例删掉，换成你自己的材料**。

**材料放在别处**：改 `config/settings.json` 的 `corpus_globs`（数组），或设环境变量（多个用分号隔开）：

```powershell
$env:TP_CORPUS_GLOBS = 'D:\面试材料\**\*.md;D:\面试材料\**\*.txt'
```

### 4.6 填三份 `config\*.md`

| 文件 | 写什么 | 不填的后果 |
|---|---|---|
| `config/company.md` | 目标公司业务 / JD / 技术栈 / 面试官是谁 | 设计题不会「结合他们的业务」，但也不会硬扯 |
| `config/known_terms.md` | **我会、但材料里没写**的技术名词 | 问到你天天在用的东西，可能被判成「没准备过」而回答「我没接触过」 |
| `config/never_used.md` | **材料里写了、但我其实没做过**的名词 | 命中走「坦诚」话术；不填就可能顺着材料吹自己没做过的事 |

格式规则（`server/answer.py` 的 `_load_list()` 就是这么解析的）：

- 一行一个词，**空格 / 逗号 / 顿号 / 斜杠都能分隔**；`#` 后面是注释。
- 以 `>`、`-`、`*`、`|` 开头的行会被跳过（所以文件开头的说明文字不会被当成词条）。
- 少于 2 个字符的词会被忽略；大小写不敏感（内部按小写比对）。
- 英文按词边界匹配，中文按子串匹配。
- 同一个词同时出现在两张表里时，**按「没做过」处理**（`never_used` 优先）。

生成候选清单（会前 2 分钟）：

```powershell
.\.venv\Scripts\python.exe -X utf8 tools\build_terms.py
```

它会输出 `config\terms_review.md`：材料里出现过哪些技术名词、哪些材料里没有。**会的抄进 `known_terms.md`，没做过的抄进 `never_used.md`**。材料本身是转写稿时专名常有错字，标一遍等于把「我不会的东西」锚死。

`tools/preflight.py` 的「专名词表体检」会替你抓两类脏数据：混进说明文字的超长 / 带标点行，以及两表冲突的词。

### 4.7 跑自检

```powershell
# 全量（含 ASR 真识别与浮窗自检，约 20~40 秒）
.\.venv\Scripts\python.exe -X utf8 tools\preflight.py

# 快速（跳过最慢的两项：ASR 识别、浮窗自检；本机约 7.6 秒）
.\.venv\Scripts\python.exe -X utf8 tools\preflight.py --fast
```

10 项检查，逐项 PASS / FAIL / WARN / SKIP + 耗时；**有 FAIL 时退出码为 1**（WARN / SKIP 不影响退出码）：

| # | 检查项 | 说明 |
|---|---|---|
| 1 | 回环采集设备存在 | 打不开回环设备直接 FAIL |
| 2 | 当前有声音在放 | 采样 1 秒算 RMS；低于 VAD 阈值只是 WARN（采集本身是通的） |
| 3 | ASR 模型加载 + 识别 | **--fast 跳过**；模型目录不存在 / 没有 `.onnx` 权重是 FAIL |
| 4 | BM25 检索索引 | 语料 0 块是 FAIL；换成你自己的材料后，它会拿第一个切块的文件名当查询自检，仍然成立 |
| 5 | 专名词表体检 | 脏行 / 两表冲突是 WARN |
| 6 | 题库新鲜度 | 题库比材料旧（或还没建过）是 WARN |
| 7 | DeepSeek 快答线 | 真调一次；密钥缺失、网络不通、额度不足都在这项暴露 |
| 8 | 端口 8765 占用 | 已被提词器后端占用是 PASS；被别的程序占用是 FAIL |
| 9 | 浮窗启动 + 截图 | **--fast 跳过**；跑的是 `ui\app.py` 的临时副本，截图落在 `.tmp\`，不碰 `ui\` |
| 10 | 全局快捷键注册 | 首选键被别的软件占用（winerr=1409）是 WARN，不是 FAIL |

常见 FAIL 的处理见 `docs/故障排查.md`；最省事的做法是面试前 30 分钟跑 `--fast` 那一版。

> 首次跑第 3 项时会看到「模型加载约 4 秒 + 识别较慢」：**首次识别含 numba JIT 编译，实测 21.7 秒**，之后降到约 100 ms。正常启动时后端会自己做预热，见下一节。

## 五、启动

### 方式 1：PowerShell 脚本（推荐）

在仓库根：

```powershell
.\scripts\run.ps1              # 起后端 + 浮窗（幂等）
.\scripts\run.ps1 --check      # 只看当前状态，不启动
.\scripts\run.ps1 --no-ui      # 只起后端（调试）
.\scripts\run.ps1 --stop       # 停掉所有提词器进程（见下面的注意事项）
```

`run.ps1` 只做三件事：定位仓库根 → 激活 `.venv` → 用 venv 的解释器跑 `tools\launch.py`，参数原样透传，退出码也原样返回。

### 方式 2：双击启动

仓库根的 `启动提词器.bat`，双击即可（等价于 `tools\launch.py` 不带参数）。出错时它会提示看 `logs\launch.log` 与 `logs\backend_console.log`；双击运行时还会自动 `pause`，让你看清报错。

### 方式 3：直接跑启动器

```powershell
.\.venv\Scripts\python.exe -X utf8 tools\launch.py
```

### 启动器为什么值得用

`tools\launch.py` 是幂等的、有健康检查、有日志：

- **不会起第二个后端**：先看 `.runtime_port` 与 8765~8769，发现已经有提词器后端在跑就直接用，不会抢端口。
- **等模型真的加载完才拉浮窗**：轮询 `/healthz` 的 `ready` 字段（不是「首页能打开」就算好，也不是死等固定秒数）。实测这能把首题墙钟从 3.8 秒降回 1.3 秒。
- **不会开出第二个浮窗**；后端与浮窗的输出都落到 `logs\`。

### 看到这些算成功

```
[00:01:12] 启动后端（加载模型 + 建索引，约 12 秒）…
[00:01:24] 后端就绪：127.0.0.1:8765（等了 12.3s）
[00:01:24] 浮窗已启动。出问题看 logs/ui_console.log；崩溃日志在 logs/backend_error.log
[00:01:24] 『 就绪 』后端 127.0.0.1:8765 + 浮窗 —— 这个窗口可以直接关掉
```

同时：屏幕上出现浮窗；仓库根多了 `.runtime_port`（写着实际端口）和 `.ui_pid`。

### 首次启动会慢：它在预热

| 项 | 实测 | 说明 |
|---|---|---|
| 模型加载 | 4.0 s | 一次性 |
| 启动预热 | 3.8 s | 用 2 秒静音先跑一次识别 |
| **首次识别（不预热）** | **21.7 s** | numba JIT 编译；**不预热等于第一题报废** |
| 预热后单次识别 | 80~115 ms（2.4~4.1 s 音频） | RTF 0.025~0.03 |

所以启动时那 8 秒是**在替你把 21.7 秒的坑填掉**，不要以为它卡住了。启动阶段还会顺手发一次 1-token 请求，把 DNS + TLS 握手挪走（实测首题墙钟 4000 ms → 1264 ms）。

> 端口 8765 被占会自动顺延到 8766~8769，实际端口写进 `.runtime_port`；浮窗每次重连都重读它，不用管。

### 第一次跑通的验收清单

| 看什么 | 期望 | 不达预期看哪 |
|---|---|---|
| 启动输出 | 出现 `『 就绪 』` | `docs/故障排查.md`「后端没起来」 |
| 浮窗 | 出现一块置顶小窗，底部有热键提示行 | 同上，「浮窗没出现 / 后端未连接」 |
| 播一段有说话的音频（视频 / 会议录音） | 浮窗底部电平条会动，并出现转写文字 | 「抓不到声音」 |
| 跑 `tools\check_audio.py` | 列出默认扬声器 + 至少 1 个回环设备 | 「抓不到声音」 |
| 说一句有材料可依的问题 | 1.3~1.5 秒内第一行答案上屏 | 「答案不出现」 |
| 按 `Ctrl+Shift+H` | 浮窗隐藏，再按一次恢复 | 「热键没反应」 |

热键（**以浮窗底部那一行显示的实际生效键为准**）：

| 键 | 作用 |
|---|---|
| `Ctrl+Shift+H` | 隐藏 / 显示（**逃生舱**：面试官让你共享屏幕就按它） |
| `Ctrl+Shift+P` | 暂停 / 恢复转写 |
| `Ctrl+Shift+D` | 深度回答（首选键被别的软件占用时会自动换，实测换成过 `Ctrl+Shift+J`，并显示在底部提示行） |
| `Ctrl+Shift+E` | 展开 / 收起详细内容 |

## 七、配置速查

配置文件：`config/settings.json`（**可选**；同目录 `config/settings.example.json` 是模板）。
**优先级：环境变量 > `config/settings.json` > 内置默认值。** 相对路径按**仓库根**解析，所以从哪个目录启动都一样。

| 键 | 默认值 | 说明 |
|---|---|---|
| `model_dir` | `<仓库根>/models/SenseVoiceSmall-onnx` | ASR 模型目录，**必须纯 ASCII** |
| `api_key_file` | `<仓库根>/config/api_key.txt` | DeepSeek 密钥文件 |
| `base_url` | `https://api.deepseek.com` | OpenAI 兼容接口地址（走网关 / 代理时改） |
| `llm_model` | `deepseek-flash` | 不要换成思考模型（实测首字约 6690 ms，面试等不起） |
| `corpus_globs` | `knowledge/**/*.md`、`knowledge/**/*.txt` | 知识库语料 |
| `ports` | `[8765, 8766, 8767, 8768, 8769]` | 依次顺延，实际端口写 `.runtime_port` |
| `dsh_node` / `dsh_bin` / `dsh_home` | 空（＝关闭） | 深答线，三项全填才生效 |

环境变量：`TP_MODEL_DIR` / `TP_API_KEY` / `TP_KEY_FILE` / `TP_BASE_URL` / `TP_LLM_MODEL` / `TP_CORPUS_GLOBS`（分号分隔）/ `TP_PORTS`（分号分隔）/ `TP_DSH_NODE` / `TP_DSH_BIN` / `TP_DSH_HOME`；另有 `TP_TIMEOUT`（默认 8）/ `TP_RETRIES`（默认 1）/ `TP_FIRST_WARN`（默认 5）。

看「当前到底生效了什么值」：

```powershell
.\.venv\Scripts\python.exe -X utf8 server\settings.py
```

它会把配置文件路径、每一项来自环境变量还是文件、以及生效值全部打印出来。完整说明见 `docs/配置手册.md`。

## 八、升级 / 卸载 / 清理

### 升级到新版本

```powershell
.\scripts\run.ps1 --stop                       # 先停掉在跑的后端与浮窗
# 覆盖新版本的文件（保留 .venv / models / config / knowledge / logs）
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1 -Mirror
```

`setup.ps1` 幂等：已有的 `.venv`、模型、`config` 文件不会被覆盖，缺的依赖会自动补齐。

### 停掉进程

```powershell
.\scripts\run.ps1 --stop
```

它会清掉 `.runtime_port` 与 `.ui_pid`。如果输出「已停掉 0 个提词器进程」但进程还在（启动器按命令行特征匹配进程，仓库目录被改过名就可能匹配不到），用这条兜底：

```powershell
Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -match 'server[\\/]main\.py|ui[\\/]app\.py' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
Remove-Item .runtime_port, .ui_pid -ErrorAction SilentlyContinue
```

### 彻底卸载

```powershell
.\scripts\run.ps1 --stop
Remove-Item .venv -Recurse -Force          # Python 环境（约 1GB，重装时重建即可）
Remove-Item models -Recurse -Force         # ASR 模型（230MB）
Remove-Item .tmp, logs -Recurse -Force     # 录音片段与会话日志（含面试记录，注意隐私）
Remove-Item .runtime_port, .ui_pid -ErrorAction SilentlyContinue
# 你自己的东西，确认不需要了再删：
#   config\api_key.txt  config\settings.json  config\*.md  knowledge\*
```

> 只想「清干净重装」又不想丢材料时，删 `.venv` + `models` 就够了。

## 九、装完之后：诚实的预期

- **它不是「AI 替你面试」**：材料外的东西它会坦白说没做过，不会编经历 —— 这是刻意设计。
- **它不认识你没写进去的项目**：材料里没有的具体数字与细节，检索不到就不会有。
- **ASR 会写坏专有名词**：`config/known_terms.md` 是唯一的兜底手段，值得会前花两分钟。
- **话题续接仍是主要未解问题**：面试官突然跳到另一个项目时，检索可能还在旧话题上。
- **路由与检索指标是在同一场真实面试数据上调出来的**，换一场面试必须重跑 `tools\regress.py` 才有意义。
- **真实面试音频上的 ASR 准确率尚未测过**（手上只有转写稿，没有原始录音）。
- **防共享只对截屏 / 录屏生效**，挡不住「共享整个桌面 / 采集卡 / 放大镜」。逃生手段始终是 `Ctrl+Shift+H`。
